# WPS C++ 编码规范（2026 高校版）

将用户指定规范作为 C++ 新代码的默认约定，并在交付前自审修改范围。
原文：[C++编码规范（2026高校版）](https://365.kdocs.cn/l/ccsMRFK0iQLx?openfrom=docs)。
本地规则依据 2026-10-24 阅读的 17 页、文档版本 6 整理，不依赖每次联网。

## 应用方式

1. 确认任务涉及的 C++ 标准版本、项目命名前缀、现有接口、构建方式，以及适用的 `AGENTS.md`、格式配置和项目约束。
2. 阅读 [完整规则](references/rules.md) 中的命名、注释、格式及本次涉及的章节。处理头文件、内存、跨平台或原文冲突时同时阅读 [来源与纠错](references/source-notes.md)。
3. 按规则实现当前任务。原文的“禁止/必须/不允许”视为要求，“建议/推荐/尽量/优先”保留为偏好，不能把建议升级成无条件禁令。
4. 仅检查、修改当前任务涉及的自有代码；不因启用 skill 而批量重排整个仓库、修改生成文件或第三方源码。
5. 按下方检查表自审，并运行与改动相称的项目构建、测试或静态检查。明确哪些已验证、哪些未运行。

用户当前明确指令和适用项目约束优先；单纯看到旧文件风格不同，不等于取消用户选定的规范。涉及兼容性时保留框架固定名称、覆写签名、公开 ABI/API、序列化名称、系统入口（如 `main`）等，简要说明必要例外。不要为统一命名破坏调用者。

原文存在少量冲突和不可编译示例。按 [来源与纠错](references/source-notes.md) 做有记录的最小修正；不能把一般个人偏好或其他风格指南冒充原文要求，也不要为遵从示例而引入编译错误、未定义行为或不安全的生命周期。

## 编写时的关键约束

- **命名**：文件名全小写；类名采用项目约定前缀和大驼峰，对外类的前缀全大写；COM 接口加 `I`。变量小驼峰，非静态成员 `m_`，静态成员 `s_`，全局 `g_`，文件静态全局 `gs_`。类型信息前缀仅为建议。成员函数小驼峰，非成员函数大驼峰，命名空间简短全小写，宏全大写。禁止以 `My` 或个人姓名作这些名称的前缀。
- **格式**：使用实际 Tab 缩进/对齐，Tab 无法精确对齐时用空格补齐；花括号上下对齐、独占行。单语句 `if` 分支不加花括号；同一条件链任一分支包含多条语句时全部加花括号。保持语义，不能产生悬空 `else`。命名空间内不额外缩进。
- **细节**：推荐每行不超过 120 字符；构造初始化列表和多基类列表的续行逗号前置，与冒号对齐；多行布尔表达式的 `&&`、`||` 放行首；预处理指令顶格。指针声明采用 `Type *pointer`。不滥用空行或连续空行。
- **头文件**：使用 `#ifndef/#define/#endif`，不以 `#pragma once` 替代。原文双下划线宏名存在保留标识符问题，按来源说明处理。能用少量合法前置声明解决的依赖不强行 include；保持头文件可独立使用。按原文正文顺序分组，组间空行。
- **类与函数**：初始化所有成员；复杂初始化默认移至由调用者检查结果的 `init()`。无隐式转换需求的单参构造函数加 `explicit`；无复制需求则禁用复制。仅用 `public` 继承，有虚函数即有虚析构，覆写声明同时标 `virtual`、`override`。输入参数在前、输出在后，输入引用加 `const`，不引入默认参数或输入输出混用参数。内联函数最多 10 行，推荐一行，不含循环、switch 或递归。
- **实现**：优先错误码，尽量避免异常；不使用 RTTI；优先明确的 C++ cast，避免 `reinterpret_cast`。尽量用常量、枚举或内联替代宏，常量优先 `constexpr`。尽量不返回类成员的指针/引用。
- **注释**：默认英文、代码注释用简洁 `//`，解释复杂逻辑和必要偏离，不逐句翻译代码。新文件头包含文件名、真实创建者、日期、功能与合法版权信息；身份或权属不明时遵循来源说明，不伪造。
- **资源与平台**：单个堆对象用 `std::unique_ptr`，连续动态存储用容器，字符串用标准字符串或 `QString`；禁止显式 `new[]/delete[]` 和 `malloc/free`。空指针用 `nullptr`。不硬编码路径分隔符或中文业务文本；平台 API 用宏隔离；关注类型宽度、线程同步和 UI 的 DPI。

这些是执行入口，完整细则和限定条件见 [完整规则](references/rules.md)，不能仅依赖摘要作出“全部合规”的结论。

## 交付前自审

- 命名、前缀、枚举成员及 getter/创建函数命名符合对应规则；接口例外有依据。
- include guard、include 顺序、前置声明和命名空间使用正确。
- 成员与局部变量初始化，复制策略、虚析构、参数方向及所有权清晰。
- 实际 Tab、花括号、短 if、换行和空格与规则一致；不把自动格式化通过当成语义验证。
- 未新增裸数组分配、手工 malloc/free、空容器越界访问、悬空引用、共享状态竞争或平台假设。
- 注释和文件头信息真实，无无用代码、无意重复代码和未处理的规范冲突。
- 已运行的构建/测试给出真实结果；未运行时说明原因，不能宣称已经通过。

普通编码任务完成后简述实现和验证即可，不重复输出整份规范。规范审查任务按“位置—对应条款—问题—修正建议”报告，区分明确违规、建议和兼容性例外。

# 完整规则与原文定位

来源为《C++编码规范（2026高校版）》版本 6，阅读日期 2026-10-24。
下文是按原文节号整理的执行性转述，页码对应当时的 17 页布局。原文未规定的细节不要自行宣称为原文要求。
“要求”包括原文明示的禁止项和无条件指令；“偏好”保留建议、尽量、优先等强度。示例矛盾和实施限定另见 [来源与纠错](source-notes.md)。

## 1 命名（第 1—4 页）

### 1.1 文件

- 文件名全小写，例如 `kctlinechartview.h`；不要照抄后面示例中的大小写不一致。

### 1.2 类

- 使用前缀加大驼峰命名，例如 `KCTLineChartView`。
- 暴露给其他工程的类使用工程约定的全大写前缀，不凭空把所有项目统一为 `KCT`。
- 尽量用完整英文单词，常见缩写例外。
- COM 接口在普通前缀前加 `I`，例如 `IKCTLineChartView`。

### 1.3 其他类型

- `struct`、`typedef`、`enum` 的类型命名同类。
- 枚举成员用大驼峰，名称中体现枚举名；枚举名在成员名称中的位置不限，同一个枚举内保持一致。例如 `ActionType` 的 `InsertActionType`、`DeleteActionType`。

### 1.4 变量

- 变量小驼峰，用能表达含义的完整英文单词；**建议**加类型前缀，例如 `nIndex`、`pLineChartView`、`spObject`。
- 单字母变量仅允许单层 `for` 循环的 `i` 和表示坐标的 `x/y/z`；嵌套循环或其他语义用有意义的名称。
- 非静态成员：`m_dataMember`；静态成员：`s_staticDataMember`；前缀后的第一个单词首字母小写。

### 1.5 函数

- 除构造/析构外，成员函数小驼峰；非成员函数大驼峰，例如 `lineCount()` 与 `GetObjectCountInDocument()`。
- 查询信息直接通过返回值给出：名词或“名词+修饰语”，如 `title()`、`subViewAtIndex(index)`。
- 信息通过输出参数给出：`get+名词（+修饰语）`，如 `getSubViews(&outPointer)`。原文另有 `getTitle()` 返回值示例冲突，依正文处理。
- 动作：动词加宾语；宾语是 `this` 时省略，如 `removeAllSubViews()`、`setTitle(...)`、`initialize()`。
- 状态：`is/has` 等加形容词/名词，如 `isVisible()`、`hasTitle()`。
- 返回对象指针且内部新分配内存的函数，名称用 `copy/create` 等反映分配行为；借用已有对象和新建对象的命名应可区分。

### 1.6 宏

- 原则上全大写，必要时以下划线分词，例如 `SOMETHING_USED`。
- 没有必要不把代码段定义为宏。

### 1.7 全局变量

- 全局变量前缀 `g_`；`static` 全局变量前缀 `gs_`。使用限制见 7.3。

### 1.8 名称空间

- 简短的全小写英文单词，例如 `chart`。

### 1.9 禁止的前缀

- 不用 `My` 或工程师个人姓名作为上述命名的前缀。

## 2 头文件（第 4—6 页）

### 2.1 包含保护

- 所有头文件用 `#ifndef`、`#define`、`#endif` 防重复包含。
- 原文宏形式为 `__PROJECTNAME_FILENAME_H__`，示例 `__KPROJECT_KHEADER_H__`；其保留标识符冲突和可移植替代见 [来源说明第 3 项](source-notes.md)。
- 文件尾部 `#endif` 注释标明 guard 名。

### 2.2 前置声明

- 一两个前置声明即可满足编译要求时，避免在头文件包含另一头文件。
- 此要求的实施前提是前置声明合法且足够；按值成员、继承、需要完整类型的操作仍直接包含必要定义，不自行前置声明标准库类型。

### 2.3 包含顺序

- 按正文：预编译头（工程已有时，如 `stdafx.h`）→与实现文件同名的头→系统头→本工程其他头；组间空行。
- 原文例子另列外部工程头，置于系统头后、本工程其他头前。
- 同名头和系统头在原文示例中顺序相反；按正文执行。不要为满足示例无故引入预编译头或 Qt。

## 3 类（第 6—7 页）

### 3.1 初始化

- 所有成员变量必须初始化；只有数据成员没有函数的类也须定义默认构造函数。
- 除特殊需求，构造函数只做不涉及具体功能的基础初始化。
- 复杂初始化放到独立的 `init()`，由创建者负责调用并检查结果；不要让失败后对象被当作已就绪使用。

### 3.2 构造与复制控制

- 单参构造函数没有明确隐式转换用途时加 `explicit`。
- 没有明确复制需求时，在 `private` 段声明拷贝构造和赋值运算符，禁止无意复制。现代 C++ 的 `= delete` 写法见来源说明。

### 3.3 继承

- 仅使用 `public` 继承。
- 语义明确时可继承实现，其余优先继承抽象接口。
- 有虚函数的类，其析构函数也定义为虚函数。
- 覆写父类虚函数时，子类声明同时写 `virtual` 和 `override`。

### 3.4 运算符重载

- 尽量避免，原文例外为在容器类中使用而必须实现的运算符。

### 3.5 声明顺序

- 按 `public`、`protected`、`private` 顺序，各访问权限只占一段。
- 每段依次：`typedef/enum/Q_OBJECT` 等声明 → 嵌套类 → 常量 → 构造函数、析构函数、成员函数、数据成员。
- 不为凑顺序创建没有用途的空段；Qt 宏访问权限等约束需保证生成代码和编译正确。

### 3.6 友元

- 友元定义与友类定义放在同一文件。

## 4 函数与实现（第 7—8 页）

### 4.1 参数

- 输入在前、输出在后；输入引用配合 `const`。
- 不使用默认参数；不让一个参数兼任输入和输出。
- 复杂类型通过引用避免不必要复制；不把这句话推广成所有小标量都必须引用传递。

### 4.2 内联

- 内联函数不超过 10 行，推荐仅内联一行函数。
- 不包含循环、`switch/case` 或递归。
- 类定义体内实现的函数不再写 `inline`。

### 4.3 异常

- 尽量避免 `try/catch` 异常处理，优先返回错误码；这是偏好，不应靠删掉必要捕获造成异常逸出或资源泄漏。

### 4.4 类型

- 不使用运行时类型信息（RTTI）。
- 明确使用 `static_cast`、`const_cast`；避免 `reinterpret_cast`，谨慎对待 `dynamic_cast`。新代码不主动引入依赖 RTTI 的 downcast；原文内在张力见来源说明。

### 4.5 宏替代

- 尽量用 `const`、`enum`、`inline` 替代 `#define`；常量优先级另见第 11 节。

### 4.6 成员暴露

- 避免成员函数返回指向类数据成员的指针或引用。

## 5 注释（第 8—9 页）

### 5.1 文件头

- 包含文件名、创建者、创建时间、功能描述、版权信息。
- 真实元数据缺失时按来源说明处理，不能把示例作者邮箱、公司版权或历史日期复制成当前文件事实。

### 5.2 代码注释

- 使用简洁清晰的 `//`；非必要不注释。
- 需要解释：刻意偏离规范、多步任务、复杂逻辑、反直觉实现、重要注意事项。
- 文件头可采用原文块注释样式，代码注释默认 `//`。

### 5.3 语言与署名

- 默认英文。
- 工程师姓名仅用于文件头创建者或 TODO 注释；TODO 可用 `// TODO(Name): ...`，但不得编造负责人。

### 5.4 预处理注释

- 条件编译块较长时，在 `#else`、`#endif` 后注释宏名。

## 6 格式（第 9—13 页）

### 6.1 对齐与缩进

- 用实际 Tab 对齐；原文未规定 Tab 显示宽度，沿用项目设置，不杜撰固定宽度要求。
- 花括号上下对齐、独占行，不接在 `if` 等语句末尾。`else` 与 `do/while` 的相应部分按原文示例另起行。
- 构造初始化列表及多基类列表的续行逗号放行首，与冒号对齐。
- 单行语句的 `if` 不加花括号；同一条件链任一分支有多条语句，所有分支都加花括号。实际布局采用另起一行的语句，不压成 `if (...) action();`。
- 推荐每行不超过 120 字符。
- 长函数参数列表可每行一个，或合理合并部分参数；返回类型、函数名、左括号保持同一行；尾部 `const` 与最后一个参数同一行。
- 预处理指令顶格。
- 多行布尔表达式将 `&&`、`||` 放续行开头；在优先级最低处断行，尽量不拆配对括号；复杂条件用括号显式标明高优先级运算。
- 命名空间内容不额外缩进。

### 6.2 空格

- 函数名与调用括号之间、括号内侧不加空格；参数逗号后一个空格。
- `if/while/for` 等与左括号之间一个空格；括号内侧不加空格。
- Tab 不能刚好对齐时用空格补齐；空参数列表写 `()`。
- 二元运算符两侧各一个空格。
- `++/--` 与变量、紧随的分号之间不加空格。
- `.`、`->` 两侧无空格；一元取地址/解引用符号 `&`、`*` 后不加空格。
- 指针声明 `*` 前一个空格，后不加空格：`KCircle *pCircle = nullptr;`。
- 原文未独立明确所有引用声明布局；与现有项目兼容时采用 `const Type &value`，属于执行约定而非新增原文条款。

### 6.3 空行

- 禁止滥用空行及连续空行。
- 建议空行用于 include 分组、命名空间边界、访问权限段/成员类型之间、函数实现之间、函数内独立逻辑步骤之间，以及预处理/异常处理特殊块前后。

## 7 作用域（第 13—14 页）

### 7.1 嵌套类

- 不作为对外接口暴露的嵌套类放在 `private`。

### 7.2 局部变量

- 在将要使用处声明，并在声明时初始化。

### 7.3 全局变量

- 除特殊情况，尽量不使用类类型全局变量，不使用类类型的静态数据成员。
- 可以用单例替代类类型全局变量；这是允许的方案，不是要求自动引入单例。
- 全局字符串使用 C 风格 `char`，不使用字符串类。局部/对象拥有的字符串依 9.3；不要将此要求误读为所有字符串都必须是裸数组。

### 7.4 名称空间

- `.cpp` 可使用匿名命名空间；头文件不允许。
- 避免 `using namespace` 整体导入命名空间。

## 8 模板（第 14—15 页）

### 8.1 模板声明

- 类型模板形参用 `typename`，不用 `class`。

### 8.2 适用范围

- 一般用于容器类或通用算法；其他用途需注释说明必要性。

### 8.3 嵌套类型

- 依赖类型名称前用 `typename`，如 `typename T::Iterator`。

### 8.4 继承

- 在模板派生类中调用模板基类函数，显式限定基类，如 `BaseClass<T>::doBaseAction()`。

## 9 内存（第 15—16 页）

### 9.1 静态存储

- 编译期可确定的常量数组声明为 `static`；满足常量表达式时结合第 11 节使用 `constexpr`。

### 9.2 栈存储

- 编译期能确定长度的非常量数组用栈存储。需考虑实际栈容量，不能把此偏好扩大成超大数组也必须上栈，详见来源说明。

### 9.3 堆与字符串

- 单个堆对象生命周期用 `std::unique_ptr` 管理。
- 连续动态内存用 `std::vector` 或 `QVector`，不显式调用 `new[]/delete[]`。
- 字符串用 `std::basic_string<T>` 或 `QString` 管理；全局字符串另遵 7.3。
- `delete` 只能在析构或专门内存清理函数出现；使用 RAII 后通常无需显式 delete。
- 禁止用 `malloc/free` 分配、释放内存。
- 不照搬原文错误的 `std::unque_ptr` 拼写、裸指针复制初始化或未检查空容器的 `&buffer[0]`。

## 10 跨平台（第 16—17 页）

### 10.1 路径

- 拼接路径时不写死分隔符；依赖 Qt 的模块可用 `QDir::separator()` 或项目已有路径抽象。

### 10.2 数据类型

- 不依赖平台不一致的类型宽度，例如把 `long` 当成跨平台固定宽度。按用途选固定宽度整数、大小类型或已有平台抽象，尤其检查文件格式和接口边界。

### 10.3 系统 API

- 优先 Qt 等跨平台 API；尽量避免 Windows 专有 API，必须用时以平台宏隔离。

### 10.4 字符串

- 原文优先跨平台的 `WCHAR` 字符串。只有项目确实提供这一跨平台类型及编码约定时按其使用；不能把 Windows 专有别名、`wchar_t` 固定宽度或固定编码当作标准 C++ 保证，见来源说明。

## 11 其他（第 17 页）

- 常量优先 `constexpr` 而非 `const`；非函数内部的常量优先大写。
- 禁止重复代码（原文称“重复 2 次以上”），抽取可复用逻辑；不要为了消除表面相似而合并语义不同的逻辑。
- 尽量避免超过 500 行的臃肿函数；不是将 500 行当作设计目标或健康阈值。
- 多线程读写的变量加 `atomic` 或其他原子修饰；复合状态还需正确同步，不能只加修饰符就宣称线程安全。
- 禁止高危函数。原文未提供名单；按实际 API 的边界、缓冲区和项目安全规范判断，不能假称某个自拟名单来自原文。
- 空指针使用 `nullptr`，不用 `NULL`。
- 禁止中文硬编码，注释除外。需要中文界面文本时用项目资源/翻译机制，不能为了合规擅自改变用户要求的界面语言。
- UI 大小、位置等参数考虑 DPI 缩放。
- 禁止无用变量和无用代码。

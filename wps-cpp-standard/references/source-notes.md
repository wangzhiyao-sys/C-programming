## 已核实的问题

1. **智能指针示例（1.4、9.3）**：原文写 `std::unque_ptr<CSomeObject> spObject = new CSomeObject();`，类型拼写错误，且即使改成 `unique_ptr`，裸指针也不能这样隐式复制初始化。C++14 及以后用 `std::make_unique<CSomeObject>()`；C++11 用 `std::unique_ptr<CSomeObject> spObject(new CSomeObject());`。这是恢复原本“唯一所有权”意图的语法修正。[C++ 工作草案中的显式构造函数](https://eel.is/c++draft/unique.ptr.single.ctor)。

2. **getter 与 include 示例（1.5、2.3）**：`getTitle()` 直接返回值的例子与文字规则冲突；新接口按正文使用 `title()`，输出参数形式才用 `get...`。include 示例把 `<vector>` 放在同名头前，且有 `KClass.h` 大写与 `kfirendclass.h` 拼写不一致；执行正文顺序与全小写文件名，引用磁盘上真实文件名，不以错误示例重命名依赖。

3. **guard 名称（2.1）**：原文是 `__PROJECTNAME_FILENAME_H__`。双下划线标识符保留给实现使用，这是原文规范与标准 C++ 的冲突。[C++ 工作草案 lex.name](https://eel.is/c++draft/lex.name)。新建通用/跨平台头文件采用 `PROJECTNAME_FILENAME_H_` 这一最小可移植修正，仍用原文要求的三段 include guard；说明该命名与原文的差异。若受课程检查器或既有工程显式规则约束，按具体要求处理并保留冲突说明，不能宣称原文字面格式就是 ISO 可移植写法。

4. **复制控制（3.2）**：原文在 private 声明拷贝构造/赋值以阻止复制。C++11 及以后可在 private 显式 `= delete`，保留原文禁用复制的语义并产生编译期诊断。不要无需求为所有类添加移动能力，也不要删掉业务确实需要的复制语义。

5. **文字笔误与过时示例**：3.5 的“虚构函数”按“析构函数”理解；其他示例中的 `Class`/`class`、继承冒号和变量拼写须按合法 C++ 修正。7.2 示例出现 `NULL`，按第 11 章明确要求用 `nullptr`。示例中的单字母模板类型形参不属于 1.4 的运行时变量限制。

6. **RTTI 与 dynamic_cast（4.4）**：原文同时说不使用 RTTI 和小心使用 `dynamic_cast`。默认不引入依赖 RTTI 的向下转换；现有外部接口确有需要时查项目 RTTI 配置并说明例外。不得为消灭 `dynamic_cast` 而替换为未经类型保证的 `static_cast`，也不能随意去除实际只读对象的 const 属性。

7. **文件头身份与版权（5.1）**：示例邮箱、日期不是可复用的真实署名。修改已有文件保留真实作者/版权。新文件优先项目已有模板和已知真实信息；缺失且任务又必须提交完整署名时集中询问。临时示例可省略无法确认字段并明确这一限制，不伪造作者、不自称金山版权所有、不把生成时间冒充原文件创建时间。

8. **格式与正确性（6）**：单语句省略花括号仅在不会改变控制流含义时实行；多行嵌套、悬空 else 等情况保留必要花括号并说明。原文没有规定 Tab 宽度、文件编码或换行符类型；沿用项目约定，不把个人设置写成规范事实。

9. **内存与生命周期（7、9）**：静态/栈优先不覆盖栈容量、线程安全和生命周期约束；巨型缓冲区用受管理堆存储并说明例外。获取连续存储地址时用合适的 `data()` 等接口，并核实空容器、长度和被调 API 的约束，不照抄空容器上的 `&buffer[0]`。两阶段初始化保留清理路径；不要为了把所有初始化挪出构造函数而破坏 RAII。

## 可核对的最小示例

以下是实现说明示例，不是原文逐字代码。注释为英文、成员小驼峰、非成员大驼峰、私有成员 `m_`、实际 Tab 缩进、花括号独占行，单语句 if 不加花括号。`main` 保留标准入口名。

```cpp
#include <memory>

class KCounter
{
public:
	explicit KCounter(int initialValue)
		: m_value(initialValue)
	{
	}

	int value() const
	{
		return m_value;
	}

	void increment()
	{
		++m_value;
	}

private:
	KCounter(const KCounter &) = delete;
	KCounter &operator=(const KCounter &) = delete;

	int m_value;
};

int ReadValue(const KCounter &counter)
{
	return counter.value();
}

int main()
{
	std::unique_ptr<KCounter> spCounter(new KCounter(0));
	spCounter->increment();
	if (ReadValue(*spCounter) != 1)
		return 1;
	return 0;
}
```

该示例采用 C++11 直接构造；项目为 C++14 及以后时可改用 `std::make_unique`。它只验证小范围语法/行为，不代替真实工程测试。
